# 검토 가능한 PR과 실제 완료

구현 완료와 리뷰·머지·마감에 사용한다. 담당 세션은 `pr` 스킬이 있으면 PR 작성에 함께 적용하고, 저장소의 템플릿·검증·승인 규칙을 확인한다. 이미 받은 유효한 사용자 승인은 재사용한다.

## PR 결과물

제목은 변경의 핵심 70자 이내, 기본 assignee는 본인(`@me`). 본문은 리뷰어가 대화를 읽지 않아도 판단할 수 있게 다음 내용을 필요한 분량으로 정리한다.

1. **문제와 결과:** 어떤 상황에서 무엇이 불편하거나 틀렸고 이번 변경 후 어떻게 되는지. 관련 이슈 링크.
2. **주요 결정과 이유:** 결과를 좌우한 선택·대안 대비 이유·합의한 업무 정책. 사소한 구현 결정을 나열하지 않는다.
3. **범위와 검토 지점:** 영향 받는 흐름·예외·중요한 위험, 이번에 하지 않은 후속 범위.
4. **실제 검증:** 검증한 커밋·관련 테스트/타입/CI 결과·핵심 동작 증거. 캐시·미실행·실패 후 수정/재검증을 성공 주장과 구분한다.
5. **필요한 화면·동작 증거:** 대표 시나리오 전후 이미지와 짧은 설명, 실제 UI 확인 결과. 화면 변경이 없으면 억지로 스크린샷을 만들지 않는다.

PR에는 대표 화면만 담고 상세 로그·여러 상태 캡처는 링크로 연결한다. 같은 fixture·화면 크기·글꼴·상태와 정확한 전후 리비전을 기록한다. 새 화면은 기존 진입·업무 흐름과 새 흐름을 비교할 수 있다. 변경 전 이미지가 없으면 재현 가능한 기준 버전에서 확보하거나 부재와 검증 한계를 밝힌다. 새로 그린 mockup을 실제 이전 화면이라고 하지 않는다.

GitHub에서 실제 볼 수 있는 저장소 이미지나 승인된 첨부 방법을 사용한다. 로컬 절대 경로를 GitHub 이미지 URL인 것처럼 쓰지 않는다. 사용자 데이터·시크릿을 노출하지 않으며 합성 fixture와 필요한 범위만 공유한다. PR 생성 후 앱의 attach_artifact가 있으면 연결하고 실제 URL·head·draft·assignee를 확인한다.

## 독립 리뷰와 변경 후 검증

담당 세션은 자기 리뷰로 요구·범위·중요한 선택·증거를 정리한다. 조율자는 구현자와 다른 읽기 전용 reviewer를 배정하고 고정 BASE/HEAD·승인 범위·관련 지침·증거 경로를 전달한다. 적대 리뷰가 필요한 위험에는 적합한 판단 모델을 사용한다. 스타일·기존 문제·타입/린터가 잡는 내용과 실제 결함을 구분한다.

지적은 조율자가 실제 재현·계약·영향으로 판단하고 수용한 것만 기존 writer가 수정한다. 수정 후 새 고정 HEAD와 delta·관련 회귀 검증을 받아 재리뷰한다. 통합 변경이 작고 원래 검토한 코드가 동일하면 동일성·통합 경계 검토로 근거를 이어가되, 예전 SHA의 CI를 현재 SHA의 통과로 표시하지 않는다.

최신 main 통합은 충돌·정책·필수 검사에 필요한 범위에서 수행한다. 공용 migration 번호·snapshot/journal·seed 한 번 적용과 API/생성 client·저장 snapshot 경계를 보존한다. 양쪽 화면이 변경됐다면 합친 소스로 렌더를 생성하고 한쪽 이미지를 일괄 선택해 덮지 않는다. 필요한 검증을 통과한 뒤 변화·실패·새 우려 없이 전체 테스트를 반복하지 않는다.

## 머지 차례

조율자는 다음 사실을 확인하고 원장에 `PR + exact HEAD + 실행자`의 머지 차례를 기록한다.

- 현재 구현이 승인 범위와 완료 기준을 만족하고 필요한 사람 결정이 실제로 있음
- 독립 리뷰의 지적을 판단·해결했고 최종 코드와 검토 근거가 대응됨
- 현재 PR HEAD의 필수 CI·브랜치 보호·PR 리뷰 결과 확인; draft의 skipped 리뷰는 완료로 간주하지 않음
- 최신 대상 브랜치와 충돌·실제 통합 위험 해결, 다른 머지와 실행 순서 확보
- PR 본문·증거가 최종 범위를 설명함

ready 전환으로 리뷰/검사가 실행되면 그 결과까지 확인한다. AI 리뷰 코멘트도 실제 근거로 판단하며 자동 판정을 맹신하지 않는다. 보호 우회·force push·새 비밀 발급으로 게이트를 통과시키지 않는다.

worker는 허용된 동일 HEAD에만 머지를 실행한다(`gh`이면 `--match-head-commit`). 차례를 받은 뒤 커밋이 바뀌거나 새 미결 조건이 생기면 조율자에게 돌려준다. 조율자 직접 실행 시에도 같다. 기술적으로 머지 가능하다는 상태와 실제 MERGED를 구분한다.

## 마감 근거

담당 세션은 PR URL·reviewed HEAD·merge SHA/시각·검증·주요 결정·후속 범위·남긴 테스트 자원을 report/status에 남긴다. 조율자는 실제 PR MERGED·SHA·대상 브랜치를 재조회한 뒤 티켓 전체 완료 기준을 확인한다. Linear 본문을 새로 읽어 맥락을 보존하고 완료 근거/PR을 갱신·Done 저장·재조회한다. 남은 별도 소비자 기능·운영 배포를 완료했다고 하지 않는다.

설계만 맡긴 작업은 설계 결과·사용자 합의·후속 실행 조건을 보고한다. 원 이슈가 구현까지 요구하면 설계 완료만으로 Done 처리하지 않는다. 사용자 확인용 서버·앱은 필요가 끝났는지 확인하고 소유 자원만 정리한다. 모든 묶음이 끝나면 이 런의 자동 감시를 실제 중지하고, 세션 정리는 사용자 정책에 따른다.
