# 디스패치 브리프 템플릿

세 종류 — 조사, 구현, 리뷰. `[ ]` 는 조율자가 채우는 슬롯이고, **REQUIRED** 표시가 붙은 슬롯이 비면 보내지 않는다. 산출물은 파일 경로로 넘기고 리포트도 파일로 받는다. 스크래치패드 경로는 세션 시스템 프롬프트의 것을 쓴다.

## 공통 조항 (모든 브리프 끝에 그대로)

```
[규칙]
- /Users/ethan/workspace 아래 primary 체크아웃은 수정하지 않는다. 쓰기가 필요하면 [지정한 worktree/스크래치 경로]에만 쓴다.
- git stash 를 쓰지 않는다 (stash 는 저장소 전역이라 남의 브랜치 stash 가 튀어나온다). 임시 대피가 필요하면 파일 복사나 별도 커밋으로.
- 서브에이전트를 스폰하지 않는다 — 구현 보조도, 리뷰어도. 리뷰는 조율자가 따로 보낸다.
- 툴 호출 예산: 약 [N]회. 넘길 것 같으면 멈추고 BLOCKED 로 보고한다.
- 막히면 같은 시도를 반복하지 말고 NEEDS_CONTEXT 또는 BLOCKED 로 보고한다.

[리턴 계약 — 최종 메시지는 15줄 이내]
상태: DONE | DONE_WITH_CONCERNS | BLOCKED | NEEDS_CONTEXT
커밋: [SHA 목록 또는 없음]
테스트: [실행한 명령과 결과 한 줄]
리포트: [리포트 파일 경로]
우려: [있으면 한 줄씩]
```

## 조사 워커

`model`: **REQUIRED** — 축약·집계는 `haiku`, 코드베이스 탐색·문서 조사는 `sonnet`, 원인 판정은 `opus`. 읽기 전용이면 `Explore` 에이전트 타입이 더 싸다(CLAUDE.md·git status 를 생략한다).

```
[목표]
[한 문장. 무엇을 알아내면 끝인지 — "X 의 원인을 종류별로 분류하고 종류마다 대표 사례 1건과 건수"]

[조율자만 아는 사실]
- [파일 경로, 도메인 제약, 이미 시도해서 실패한 접근, 관련 커밋]

[도구·소스]
- [읽을 파일/디렉터리/URL] — 이 밖은 보지 않는다.
- [40MB 로그처럼 컨텍스트에 안 들어가면] 먼저 grep/awk 로 축약 파일을 만들고 그것만 읽는다.

[경계]
- 판정하지 않고 사실만 모은다 / 또는: 판정하되 근거 없는 판정은 "보류"로 적는다
- 코드를 수정하지 않는다

[출력]
- 상세는 [스크래치패드/…-report.md] 에 쓴다. 형식: [표 컬럼 또는 섹션 목록]
- 최종 메시지는 리턴 계약대로 15줄 이내.
```

## 구현 워커

`model`: **REQUIRED** — 브리프에 코드·값이 다 있으면 `haiku`, 산문 요구사항에서 만들면 `sonnet`, 다중 파일 통합·디버깅이면 `opus`. 결제·인증·마이그레이션·동시성을 건드리면 diff 크기와 무관하게 `opus`.

디스패치 전에 `git rev-parse HEAD` 를 BASE 로 기록한다 — 리뷰 diff 는 `BASE..HEAD` 로 뜬다(`HEAD~1` 은 여러 커밋짜리 태스크의 앞 커밋을 조용히 버린다).

```
[이 태스크의 위치]
[한 줄 — 어느 계획의 몇 번째, 앞 태스크가 남긴 인터페이스]

[요구사항]
[브리프 파일 경로 — "이 파일이 요구사항이다. 안의 값은 그대로 쓴다."]
또는 여기에 직접: 바꿀 파일, 기대 동작, 테스트 케이스, 정확한 값·시그니처

[조율자만 아는 사실]
- [앞 태스크의 결정, 브리프의 모호한 부분에 대한 조율자의 해석, 건드리면 안 되는 곳과 그 이유]

[작업 위치]
- [worktree 경로 또는 "이 체크아웃의 [경로] 아래만"]
- 스테이징은 경로를 명시해서만 한다 (`git add <파일>`). `git add -A`, `-u`, `commit -a` 를 쓰지 않는다.

[경계]
- 요구사항 밖 리팩터링·기능 추가를 하지 않는다
- [예: `// includes soft-deleted` 주석이 붙은 곳은 건드리지 않는다]

[검증]
- [실행할 명령 — pnpm check-types, 관련 테스트 파일 단위 실행]
- 새로 쓴 방어·단언은 구현을 일부러 깨뜨려 기대한 테스트만 빨개지는지 확인하고 리포트에 적는다

[출력]
- 커밋 메시지: [Conventional Commits 형식과 스코프]
- 리포트: [스크래치패드/…-report.md] — 바꾼 파일, 테스트 출력 원문, 변형 확인 결과, 요구사항과 다르게 한 곳과 이유
- 최종 메시지는 리턴 계약대로 15줄 이내.
```

## 리뷰 워커

`model`: **REQUIRED** — `sonnet` 이 바닥. 결제·인증·마이그레이션·동시성·최종 전체 리뷰는 `opus`. 리뷰어는 읽기 전용이다.

리뷰 대상은 조율자 컨텍스트를 거치지 않고 파일로 만든다:

```bash
{ git log --oneline BASE..HEAD; git diff --stat BASE..HEAD; git diff -U10 BASE..HEAD; } > [스크래치패드/…-review-package.md]
```

```
[리뷰 대상]
- diff 와 커밋 로그: [review-package 경로]
- 요구사항: [브리프 경로]
- 구현자 리포트: [리포트 경로] — 미검증 주장으로 읽는다. 리포트의 설계 근거("YAGNI 라서 뺐다", "의도적으로 단순하게")는 발견의 심각도를 낮추지 않는다. 코드 자체로 판단한다.

[리뷰 축]
- 요구사항 일치: 브리프의 항목마다 diff 에 대응 hunk 가 있는가. 없는 항목은 그 자체로 Missing 발견이다.
- 정확성: [이 변경에서 특히 볼 것 — 예: invalidateQueries 의 queryKey 가 실제 키와 일치하는가, onSuccess 가 아니라 onSettled 여야 하는 경로가 있는가]
- 범위: 요구사항 밖 변경이 섞였는가

[오탐 범주 — 이건 올리지 않는다]
- 린터·타입체커·컴파일러가 잡는 것
- diff 밖 기존 문제
- 스타일·네이밍 취향, 시니어가 지적하지 않을 사소한 것
- 변경의 의도에 직접 따라오는 동작 변화

[하지 않는 것]
- 테스트 스위트를 다시 돌리지 않는다. 구현자 리포트의 테스트 출력이 증거다. 읽다가 구체적 의심이 생긴 곳만 그 테스트 하나를 돌린다.
- 워킹트리·인덱스·HEAD 를 바꾸지 않는다.

[출력]
- 발견마다: 심각도(Blocking / Important / Minor) · `파일:라인` · 무엇이 잘못됐고 어떤 입력에서 드러나는지 · 확신도 0~100
- 판정: 머지 가능 / 수정 필요 / 판단 불가(이유)
- 상세는 [스크래치패드/…-review.md], 최종 메시지는 발견 목록과 판정만.
```

## 재리뷰 (수정 라운드 뒤)

전체를 다시 보지 않는다. 이전 발견 목록과 수정 diff(`이전 HEAD..HEAD`)만 주고 발견마다 `해소 / 미해소 / 새 문제 유발` 을 받는다. 라운드 1~3은 원래 구현자를 SendMessage 로 재개하고, 4~5는 한 티어 위 모델의 새 구현자에게 브리프·리포트·미해소 목록을 준다.
