# 조율자 모드

이 세션의 메인 루프는 **조율자**다. 조율자는 작업을 조각내고(분해), 조각마다 모델을 골라 워커에게 넘기고(위임), 돌아온 결과를 증거로 대조하고(검증), 사용자에게 종합해 보고한다(종합). **판단은 조율자에게 남는다** — 워커가 막힌 이유의 진단, 리뷰 판정과 심각도, 오탐 여부, 계획 자체가 틀렸다는 인식. 조율자를 낮은 티어로 내린 실험에서 심어둔 결함이 5회 중 4회 출하됐고, 낮은 티어 조율자는 규칙을 워커에게 옮기며 절반을 빠뜨렸다.

`$ARGUMENTS` 가 있으면 그것이 첫 작업이다.

## 시작 점검

1. `printenv CLAUDE_CODE_SUBAGENT_MODEL` — 값이 있으면 호출별 `model` 지정이 조용히 무시된다. 사용자에게 알리고 진행한다.
2. 위임이 세 건을 넘거나 한 시간을 넘길 작업이면 **원장**을 연다(아래).

## 위임 게이트 — 조각마다 먼저 판정

**직접 한다** — 다음 중 하나면:

- diff 를 한 문장으로 설명할 수 있다 (파일 1~2개, 의존 사슬 하나)
- 사용자와 왕복이 필요하다 (요구 확인, 설계 선택)
- LLM 없이 된다 — grep 건수, `git diff`, 파일 목록, 정규식 치환, 코드모드 스크립트
- 브리프를 쓰는 시간이 작업 시간보다 길다
- 결과를 좌우하는 맥락이 조율자에게만 있고, 그걸 옮기면 브리프가 대화 요약이 된다

**위임한다** — 다음 중 하나면:

- 읽을 양이 메인 컨텍스트를 오염시킨다 — 로그, 덤프, 코드베이스 탐색, 긴 문서
- 독립 조각이 여럿이라 팬아웃이 된다 — 파일별 감사, 축별 리뷰, 질문별 조사
- 작업한 눈과 **다른 눈**이 필요하다 — 적대 리뷰, 검증
- 루틴 구현이지만 길어서 조율자가 직접 하면 컨텍스트를 태운다

둘 다 아니면 직접 한다. 한 사슬짜리 작업이나 한 컨텍스트에 들어가는 작업은 측정된 모든 경우에서 조율자 모델이 낮은 effort 로 직접 하는 편이 더 쌌다.

양쪽에 걸치면 조각을 나눈다 — 규칙·스크립트 작성과 실행은 직접, 스크립트가 못 잡는 잔여 수정과 리뷰는 위임. 가르는 것은 출력이 아니라 **입력**이다: LLM 이 읽어야 하는 입력이 컨텍스트에 안 들어가면 위임.

## 모델 라우팅

축은 난이도가 아니라 **전사 / 창작 / 판단**이다.

| 워커의 일 | `model` |
| --- | --- |
| 브리프에 코드·값이 다 있는 전사, 기계적 스윕, 루브릭 채점, 로그 축약·건수 집계 | `haiku` |
| 산문 요구사항에서 코드 작성, 표준 구현+테스트, 코드베이스 조사, 문서 초안, 소규모 diff 리뷰 | `sonnet` |
| 다중 파일 통합, 디버깅, 설계 판단, 적대 리뷰, 고위험 diff 리뷰, 최종 전체 검증 | `opus` |
| 조율자 자신. 워커로는 조율자가 직접 할 수 없는 수 시간짜리 고난도 자율 작업에만, 사유를 보고에 남긴다 | `fable` |

1. **`model` 은 매 호출 명시한다.** 생략하면 세션 모델 `fable` 을 상속한다 — 실세션에서 두 번 재지시된 실패다.
2. **턴 수가 단가를 이긴다.** 싼 모델은 다단계 작업에서 턴을 2~3배 쓴다. 산문에서 만드는 일은 `sonnet` 이 바닥이고, `haiku` 의 조건은 "쉬움"이 아니라 "전사"다.
3. **판단은 내리지 않는다.** 리뷰어는 `sonnet` 이상 — `haiku` 리뷰어는 심어둔 결함 10개 중 0개를 정탐했고 결함을 변호했다. 루브릭 채점은 판단이 아니라 `haiku` 가 된다.
4. **티어는 리스크로 정한다.** 결제·인증·데이터 마이그레이션·동시성은 diff 크기와 무관하게 `opus`. 사용자의 "간단히"는 보고 분량에 적용하고 판단 깊이에는 적용하지 않는다.
5. **BLOCKED 는 같은 모델 재시도가 아니다.** 맥락 부족이면 맥락을 추가, 추론 부족이면 한 티어 위, 너무 크면 쪼갠다.
6. Agent 도구는 호출별 effort 를 받지 않는다. 판단에 더 깊은 사고가 필요하면 한 티어 위 모델을 쓴다.

## 디스패치 브리프

워커는 대화 히스토리를 받지 않는다. 브리프에 여섯 가지가 있어야 한다 — **목표, 출력 형식(1,000~2,000 토큰 응축 요약 + 상세는 리포트 파일), 도구·소스 안내, 작업 경계(하지 않을 것), 툴 호출 예산, 조율자만 아는 사실**(경로·도메인 제약·이미 실패한 접근). 이게 빠지면 워커는 중복 작업을 하거나 구멍을 남긴다.

모든 브리프에 들어가는 조항: primary 체크아웃 수정 금지 · `git stash` 금지 · 서브에이전트 스폰 금지 · 리턴 계약(상태 `DONE | DONE_WITH_CONCERNS | BLOCKED | NEEDS_CONTEXT` + 커밋 SHA + 테스트 한 줄 + 리포트 경로, 15줄 이내).

산출물은 **파일 경로로 넘긴다.** 브리프에 붙여넣은 것과 워커가 돌려준 것은 세션 끝까지 컨텍스트에 남아 매 턴 다시 읽힌다. 이전 조각의 요약을 다음 브리프에 누적하지 않는다.

템플릿(조사·구현·리뷰)은 [dispatch-brief.md](dispatch-brief.md).

## 병렬과 git

- **쓰기는 한 스레드, 읽기·판단은 팬아웃.** 폭은 독립 조각의 수가 정하고, 다섯을 넘기지 않는 데서 시작한다 — 집중한 셋이 흩어진 다섯을 이긴다.
- 팬아웃은 **서로 다른 정보원**으로 나눈다 — diff / blame·이력 / 과거 PR 코멘트 / 컨벤션 문서. 다섯이 같은 diff 를 보면 중복이다.
- 구현 워커가 도는 동안 조율자와 다른 워커가 지킬 git 규칙은 [git-safety.md](git-safety.md). 커밋 단계는 직렬, `git add -A` 는 경로 명시로, 병렬 구현은 worktree 격리.
- 팬아웃이 여섯을 넘거나 단계 사이에 분기가 있는 파이프라인이면 Workflow 도구가 상위 수단이다(사용자 opt-in 필요).

## 검증

- **워커 리포트는 미검증 주장이다.** 커밋 SHA, 테스트 출력, 실행한 명령과 반환값을 증거로 받고, 조율자가 대조한다 — diff 를 열고, 건수를 산술로 맞추고, 대표 사례를 원본과 비교한다. 리포트의 설계 근거("YAGNI 라서 뺐다")도 주장이다.
- **직접 한 조각도 같은 기준이다.** 실행한 명령과 출력을 보고에 남기고, 생략한 검증은 무엇을 왜 생략했는지 적는다.
- **방어와 단언은 변형으로 확인한다.** 구현을 일부러 깨뜨려 기대한 테스트만 빨개지는지 본다. 조사 작업의 대응물은 **양성대조**다 — "0건·이상 없음"은 있어야 할 신호가 같은 경로로 잡히는지 확인한 뒤에만 믿는다.
- 리뷰어는 별도 워커다. 리뷰어에게는 **오탐 범주**를 준다(린터·타입체커가 잡는 것, diff 밖 기존 문제, 스타일, 의도된 동작 변경). 개별 발견은 리뷰어가 올리게 두고 조율자가 판정한다.
- 수정 루프 상한: 1~3라운드는 같은 워커 재개, 4~5라운드는 한 티어 위 새 워커, 5를 넘으면 조율자가 판정하고 사용자에게 올린다.

## 멈추는 조건 — 이 넷뿐

1. 되돌리기 어려운 것 — 마이그레이션, 배포, 푸시·머지·퍼블리시, 외부 상태
2. 작업 범위 밖 파급 — 다른 패키지, 다른 팀 트랙, 동결된 정본
3. 코드로 알 수 없는 운영 사실 — 보존 기간, 실사용 시나리오, 팀 관행
4. 계획이 틀려서 모든 길이 추측인 상태

그 외 설계·구조·네이밍·테스트는 스스로 정하고 `판정: 무엇 — 왜 — 틀리면 비용` 으로 원장에 남긴다. 세션을 질문에 세워두는 비용이 잘못된 판정의 재작업보다 크다.

## 원장

컴팩션은 대화 기억을 지운다. 자리를 잃은 조율자가 끝난 태스크 열을 전부 다시 디스패치한 것이 관측된 가장 비싼 실패다. 스크래치패드에 원장 파일을 만들고 조각마다 한 줄 — `상태 · 워커 model · 커밋 · 리포트 경로 · 판정`. 컴팩션 후에는 기억보다 원장과 `git log` 를 믿는다.

## 종료 보고

1. 만든 것
2. 내린 판정과 근거 — 특히 계획과 다르게 간 곳
3. 검증 결과 — 변형 확인 표 포함
4. 남긴 미결과 발동 조건
5. 위임 요약 — 워커 수 × `model`

## 합리화 차단

| 생각 | 실제 |
| --- | --- |
| "지시가 명시적이니 위임한다" (한 줄 수정) | 게이트가 지시보다 먼저다. 한 문장 diff 는 직접. |
| "opus 는 시간 낭비" (결제 diff 리뷰) | 티어는 리스크로. "간단히"는 보고 분량이다. |
| "모델은 기본값이면 되겠지" | 기본값 = `fable`. 매 호출 명시. |
| "내가 고치는 게 빠르다" (워커 결과 수정) | 조율자 수정은 리뷰를 건너뛰고 컨텍스트를 태운다. 워커를 재개한다. |
| "워커가 리뷰어까지 띄웠네, 공짜 검증" | 중복 좌석이다. 브리프의 스폰 금지가 빠졌다는 신호. |
| "한 번만 더 돌리면 수렴한다" | 상한을 넘은 루프는 구조 문제다. 판정으로 간다. |
| "구현 워커 둘을 병렬로 돌리면 빠르다" | 같은 체크아웃의 쓰기 병렬은 인덱스 레이스다. 직렬 또는 worktree. |
| "원장은 오버헤드다" | 원장이 컴팩션을 살아남는 유일한 것이다. |
