# 위임 작업 마감

조율자 채팅과 작업 환경은 유지하고, 완료된 위임 작업의 증거·브랜치를 보존한 뒤 본인 자원과 작업 환경을 회수한다. 채팅 아카이브와 worktree 회수는 별도 작업이다.

## 대상과 승인

실제 정리 요청에 적용한다. 스킬 작성·설계 승인으로 현재 세션들을 정리하지 않는다. 기본 범위는 완료된 담당 세션의 본인 임시자원 회수 → worktree 아카이브 → 고정 해제 → 채팅 아카이브다. 기존 유효한 승인은 재사용하고 사용자 지정 보존 조건을 우선한다.

현재 조율 원장 또는 사용자가 명시한 세션 ID에서 대상을 찾는다. 최신 실제 사용자 지시, 보고·증거, 현재 turn·명령·대기 상태를 대조한다. 최근 목록·제목·브랜치 이름만으로 위임 관계를 만들지 않는다. 원장이 없으면 대화에서 확인되는 배정만 등록하고 불명확한 대상은 보존한다.

조율자 threadId·worktree·현재 브랜치·설정과 보존 경로를 먼저 기록한다. 조율자 환경을 유지하며 다른 작업의 변경도 그대로 둔다. 경로가 이미 없거나 상태가 다르면 그 사실을 남기고 임의 재생성·reset 없이 다음 행동을 결정한다.

## 정리 판정

| 실제 근거 | 처리 |
| --- | --- |
| 승인된 완료 기준 충족, 증거 회수 가능, 실행·질문·자원 의존 없음 | 정리 진행 |
| report는 DONE이나 미해결 작업·미푸시 커밋·미커밋 변경·PR 부재 등 완료 근거가 불일치 | 미완료로 보존, 다음 행동 기록 |
| 실제 명령·로그 진전 또는 마지막 보상정리 실행 중 | 기존 실행을 기다린 뒤 재판정 |
| 사용자·외부 조건 대기, 확인용 앱·서버가 여전히 필요 | 채팅·고정·필요 환경 유지, 해제 조건 기록 |
| 여러 채팅이 공유하거나 소유·삭제 경계 불명확 | 해당 자원 보존, 부족한 근거 기록 |
| 사용자가 미완료 작업의 중단·회수까지 명시 승인 | 변경·증거·재개 방법 보존 후 중단 상태로 정리; 완료로 표시하지 않음 |

정리 요청 자체는 미완료 작업의 폐기 승인이 아니다. snapshot이 가능하다는 이유로 미완료 세션을 닫지 않는다. 구현은 실제 PR 상태·검토 HEAD·merge SHA·대상 브랜치 포함·남은 완료 조건으로 판단하고, 설계 작업은 합의된 산출물로 판단한다. squash merge는 `git branch --merged`에 나오지 않을 수 있다. 이미 확인한 유효 근거를 재사용하고 마감을 위해 새 구현·리뷰·전체 테스트를 시작하지 않는다.

## 회수 순서와 실행 주체

1. **증거 보존.** 실제 HEAD·브랜치·변경, 결정·검증·PR/티켓·후속 범위와 필요한 로그·이미지·APK를 기록한다. 회수될 worktree 밖의 지속 경로에 필요한 파일을 보존하고 복사본을 확인한다. ignored 파일은 Git snapshot에 포함된다고 가정하지 않는다. 시크릿은 마감 기록에 복사하지 않는다.
2. **본인 자원 정리.** 기존 담당 세션이 자기 서버·DB·에뮬레이터·fixture를 기존 승인·소유 기록에 따라 회수한다. 실제 PID·command·cwd·자원 ID를 실행 직전 대조하며, 오래된 PID나 포트만으로 종료하지 않는다. 공유·운영 자원과 다른 작업은 보존한다. 외부 보상정리는 승인된 API·멱등 계약을 따르고 unknown은 원 요청과 읽기로 확인한다. 이미 성공한 정리를 다시 실행하지 않는다.
3. **worktree 아카이브.** 현재 도구의 적용 범위를 읽는다. Codex의 `list_artifacts`·`archive_worktree`가 호출 채팅에 한정되면 기존 담당 채팅에서 본인 attachment의 정확한 identityKey로 실행한다. 조율자에게 다른 채팅의 worktree를 임의 attach하지 않는다. 필요한 ignored 증거 보존과 실행·공유 의존 해제 후 복구 가능한 아카이브를 우선하고 반환 결과·복구 식별자를 기록한다. primary·pinned·shared·submodule 등 거부 조건은 보존 사유로 남긴다. 거부를 강제 삭제·`rm -rf`·`reset --hard`로 우회하지 않는다. 브랜치는 기본 보존한다.
4. **채팅 마감.** 담당 정리 turn의 종료와 결과를 회수한 뒤 조율자가 고정을 해제하고 채팅을 아카이브한다. 앱 목록·attachment 결과로 각각 확인한다. 지시 전송·채팅 아카이브만으로 자원 회수를 완료 처리하지 않는다. 본인 자원이 남으면 보존 이유·다음 행동을 남기며 전체 회수 완료라고 보고하지 않는다.
5. **감시 정리.** 이 런에 연결된 automation만 처리한다. 완료 대상은 제거하고 필요한 미완료 감시는 기존 승인 범위에서 유지·축소한다. 모든 감시 목적이 끝났거나 사용자가 중단하면 실제 중지 결과를 확인한다. 사용자 확인용 환경을 보존한다는 이유만으로 새 무기한 감시를 만들지 않는다.

담당 채팅 메시지는 사용자가 승인한 위임 작업 정리 범위에서만 보낸다. 이미 실행 중이면 기다리고 같은 지시를 중복 전송하지 않는다. 접근·권한·지원 도구가 없으면 해당 항목을 미실행으로 남기고 가능한 다른 항목을 계속한다. 서브에이전트는 앱의 독립 채팅과 구분하고 현재 런타임의 수명 관리 기능을 따른다.

## 마감 기록과 조율자 컨텍스트

기존 런 디렉터리에 조율자가 `closeout.json`과 `resume.md`를 저장한다. 파일은 임시 파일에 완전히 쓴 뒤 rename으로 교체한다. 담당 status/report의 갱신은 소유자에게 맡긴다.

- **closeout.json:** 런·조율자 ID와 유지 환경, 대상별 실제 threadId/hostId/worktree/branch/HEAD, 완료 근거, 정리 또는 보존 판정과 이유, 실행 주체, 자원별 실제 결과·영수증/증거 위치, worktree 복구 식별자, 고정/채팅/automation 상태, 미실행·남은 행동, 확인 시각. 비동기·unknown·실패는 완료와 구분하고 재실행 전 실제 상태를 재조회한다.
- **resume.md:** 현재 목표, 유지 환경·원장/마감 기록 경로, 미완료 작업과 실제 대기 주체·질문 위치·다음 행동, 유효한 승인·보존 조건. 완료 작업은 요약과 증거 링크로 남기고 과거 전체 로그를 다시 주입하지 않는다.

저장한 기록을 다시 읽어 실제 상태와 대조한 뒤 조율자 컨텍스트를 압축한다. 지원되는 압축 기능을 사용하되 직접 도구가 없으면 `resume.md` 준비 후 사용자에게 `/compact`를 안내하고 압축은 미실행으로 기록한다. 압축을 완전 초기화라고 주장하거나 조율자 채팅을 대신 아카이브·새로 만들지 않는다. 미완료·보존 항목이 있는 마감은 부분 완료로 보고한다.

예: `$close-delegated-work 이번 조율 런을 정리해. 조율자는 유지하고 완료된 위임 세션은 자원 회수 후 아카이브해. 사용자 확인용 환경은 남겨줘.`
